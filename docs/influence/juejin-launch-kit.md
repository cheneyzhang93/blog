# 掘金启动套件（Launch Kit）

> 用途：掘金账号注册、资料填写、专栏建设与每篇同步时的直接取用文案与规则。
> 原则：源站首发不变，掘金是唯一新增分发渠道（放大器）；受众可迁移——原文链接每篇必留。
> 依据：`docs/superpowers/specs/2026-09-17-tech-influence-plan-design.md` §7。

## 1. 资料页简介

**短版（≤60 字，用于签名/一句话介绍）**

> 后端工程师，记录后端架构与稳定性治理的 0→1：测试、契约、可观测性与消息可靠消费。

**长版（≤200 字，用于资料页「个人介绍」）**

> 后端工程师。博客只写一件事：系统的从 0 到 1——怎么设计、为什么这样取舍、实测结果如何、边界在哪里。每篇一个子系统，沿「设计空间 → 逐决策依据 → 机制细节 → 实测纠偏 → 边界与代价」展开；案例来自真实工程实践、已完全脱敏。完整目录与更新见博客：https://cheneyzhang93.github.io/blog/about/

链接统一指回博客 About 页（与站内身份收口一致，不散落多个入口）。

## 2. 专栏设置（两个，与站内 series 一一对应）

| 专栏 | 简介（可直接粘贴） |
|---|---|
| 稳定性治理 | 测试体系、API 契约与可观测性（日志 / 链路 / 告警）的从零建设：不改架构，也能把系统一点点稳住。 |
| 后端架构 | 消息可靠消费、批量数据修复这类工程任务的设计复盘：约束、取舍、机制细节、实测与边界。 |

## 3. 封面规范

- 尺寸 **1200×630**，与站点 og:image（`assets/images/preview.png`）同源视觉；
- 模板：`docs/influence/assets/juejin-cover-template.png`，源文件 `docs/influence/assets/juejin-cover-template.html`（内含重截命令）；
- **单篇产出方式**：改 HTML 中的系列名（`.label`）与文章标题（`h1`，中文 ≤14 字/行、最多两行），用无头 Chrome 按源文件头部命令重截 PNG——标题直出、风格零漂移、不依赖制图工具；
- 图形元素为主、留白充足，缩略图状态可读。

## 4. 发布 5 步 SOP（每篇固定）

1. **源站首发**（周四，节奏不变）：构建 + 渲染验证通过、线上可访问后再动分发；
2. **当天傍晚同步**：掘金「写文章」→ 粘贴 Markdown 导入；**逐项核验** mermaid（掘金不渲染，需导出 PNG 后替换，站内保持源码）、代码块、表格；
3. **文末附「原文首发」链接**：固定一行「本文首发于个人博客：<原文链接>」指回源站；
4. **选择专栏与标签**：专栏与站内 `series` 对齐（稳定性治理 / 后端架构）；标签 3–5 个（如 Java、后端、架构）；
5. **上传封面**：用模板生成的封面图。

## 5. 原创策略（保守优先）

- 优先勾选**原创**声明（本站为唯一首发地）；
- 若被判定疑似重复/首发冲突，改选**转载**并注明原文——两种结果下「原文链接」均保留，影响力无损；
- 规则以掘金官方帮助中心为准（https://juejin.cn/help），每次同步前对照最新版；只发本人原创内容，不搬运、不洗稿。

## 6. 存量同步节奏（W3–W6）

- **2 篇/周**、按发布时间**升序**把 7 篇存量搬完（先建作者主页与专栏基线）；
- 建议顺序：收件箱模式 → 批量数据修复 → 测试体系 → API 契约 → 日志 → 链路 → 告警；
- 新文随后即发即同步（同日晚间）。

## 7. 互动 SOP

- 发布后 **24h 内**回复评论；技术讨论认真展开，不敷衍；
- 每周固定时段回访同领域作者、参与 1–2 个话题；从评论/私信中收集下一轮选题输入；
- **不做**无意义的互赞互关、不刷量、不做标题党；数据看来源结构与互动质量，不看单篇虚荣指标。
